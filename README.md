# pi-goal

**基于 codemode 实现，零初始上下文注入，无额外工具注入。**

给 Pi 一个明确目标，让它持续推进，减少你反复输入“继续”的次数。

- **基于 codemode**：复用现有能力，按需访问目标功能。
- **零初始上下文注入**：启动会话时不预塞目标指令，设置目标后才按需提供提示。
- **无额外工具注入**：不向主模型的工具列表添加独立工具，保持原有交互方式。
- **一个目标，一条命令**：用 `/goal <目标>` 开始，无需管理任务列表或编号。

适合修复问题、完成一项功能、补齐测试等需要多轮工作的事情。
同一时间只保留一个目标，由你设置或替换。目标完成、遇到阻塞，或者你主动暂停时，停止自动继续。

## 开始使用

输入 `/goal` 加上你希望达成的结果：

```text
/goal 修复登录失败的问题，并运行相关测试确认修复有效
```

目标尽量写清楚“怎样算完成”，例如不仅要求修改代码，还要求通过哪些验证。
设置后会开始推进；再次输入 `/goal <目标>` 会替换当前目标。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/goal <目标>` | 设置或替换目标，并开始执行 |
| `/goal` | 查看当前目标、状态和累计运行时间 |
| `/goal pause` | 暂停自动继续 |
| `/goal resume` | 恢复暂停的目标，或重试受阻的目标 |
| `/goal clear` | 结束当前目标 |

`/goal parse` 也可用于暂停。

例如，需要先补充信息时：

```text
/goal pause
```

补充信息、处理好阻塞条件后，再输入：

```text
/goal resume
```

暂停或清除目标不会强制中断正在执行的工具，也不会撤销已经完成的操作。

## 查看进度

运行期间会显示目标状态和累计运行时间；暂停、受阻或完成后，自动状态提示隐藏。
随时输入 `/goal` 都可以查看详情。累计运行时间不包含暂停和离线时间。

## 为什么停下来了？

- **已完成**：目标已经达成。需要继续其他工作时，设置一个新目标。
- **受阻**：缺少信息、权限或其他必要条件。处理后用 `/goal resume` 重试；恢复不代表跳过必要的确认。
- **已暂停**：你主动暂停，或自动保护机制停止了重复尝试。确认情况后可以恢复。

遇到临时错误会自动重试；连续失败或频繁重复继续时，会暂停，避免一直消耗资源。它不保证所有目标都能自动完成。

重新打开会话或切换历史分支后，不会自动续跑；需要时用 `/goal resume` 恢复。
已完成或清除的目标不能恢复，请用 `/goal <目标>` 重新设置。
