# pi-goal

告诉 Agent 你想达到什么结果，由它自主组织和维护多级 TODO。
你不需要管理任务 ID、父子关系或逐项修改状态。

## 使用

```text
/goal 让登录功能达到可上线标准
```

| 命令 | 操作 |
| --- | --- |
| `/goal <目标>` | 新增目标并开始执行 |
| `/goal` | 查看按层级展示的计划和执行状态，不显示内部 ID |
| `/goal pause` | 暂停自动继续，不中断当前工具 |
| `/goal resume` | 恢复执行，并重新尝试受阻任务 |
| `/goal clear` | 停止自动继续，取消未完成项，保留历史 |

调整计划直接用自然语言告诉 Agent，例如：

```text
先修复 token 过期问题，再补测试。
删除刚才重复创建的测试任务。
```

Agent 通过 codemode 管理任务的新增、拆分、编辑和删除；这些不是用户命令。
旧的 `/goal add/update/delete` 和 `--parent` 写法会提示改用自然语言，
不会误当成新目标执行。内部工具接口说明见 [AGENTS.md](AGENTS.md)。

清单记录每项由用户还是 Agent 创建。Agent 修改计划不会自行恢复暂停的执行，
也不能扩大授权、绕过必要确认或重建用户已取消的工作。
新增或重写的计划项不会自动纳入持续执行范围，需要时暂停后 `/goal resume`。
运行中再次 `/goal <目标>` 会纳入新目标；重复 `/goal resume` 无副作用。
`resume` 会把受阻项重新列为待办，不恢复已完成、取消或删除的项；若阻塞条件仍在，Agent 应再次报告受阻，不绕过权限或确认。

## 自动继续保护

没有固定的模型回合总上限。整个模块共享 **10 次重复提醒预算**：

1. goal 实际新增、修改或删除时补满；重复提交相同值不算变更。
2. 仅在 goal 准备重复注入提醒的结束边界检查：无变更且两次间隔小于 **1 分钟**，扣一次；首次或变更后首次只建立基准。
3. 连续运行每满 **10 分钟**，在下一次检查时补满，补满优先于本次扣减。
4. 耗尽后暂停，用户 `/goal resume` 可补满并继续。

长间隔只是不扣预算，不会补满。普通工具回合、查询、backtrack/compact 摘要
以及其他扩展的继续不计数。暂停时间不算连续运行；不得制造无意义变更来续预算。
这是简单的空转启发式，可能误判快速正常工作。

错误最多自动重试 10 次，退避 1–512 秒；主动中断或重试耗尽暂停。
重新打开会话、切换历史分支不自动运行。backtrack/compact 后会补一条简短的状态摘要。

## 本地运行

需要 Pi 1.3.0 的 codemode 和执行边界事件，Node.js ≥22.19.0。

```sh
npm ci --ignore-scripts
npm test
pi -e ./src/index.ts
```
